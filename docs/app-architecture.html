Useful without AI

Review record for the optional job-hunt application. November 9, 2026.

Draft implementation, not a production-readiness claim. The Python package can be built without bundled UI assets. Frontend, native packaging and HTTP integration verification remain required before release.

Calibrated goal and model

Keep the existing deterministic Python CLI useful, while adding account-scoped job and short-term project workflows, learning practice and received-feedback tracking. An app account and authorization to an LLM are separate concerns. Consumer subscription login does not implicitly authorize this service to call a provider API.

The agreed approach reuses matching, ranking, tailoring and learning catalogs behind an authenticated service boundary. It never turns an existing CLI person's workspace into a shared hosted database. App data defaults to workspace/web. Owner IDs come from authenticated sessions, not client-submitted person identifiers. Existing CLI --person workflows remain separate.

Release gates and deliberate limits

Local npm installation encountered denied workspace symlinks and artifact-download errors. Windows event-loop initialization stalled inside the standard-library loopback socketpair before HTTP tests could execute. These are recorded blockers, not passing checks. Docker was unavailable on the implementation machine.

CI must execute the API tests, TypeScript checks, web build and applicable native exports. Native signing and platform toolchains are separate requirements; no binaries have been signed or published. HTTPS, a durable server secret, explicit origins/hosts, backups, verified-email/password-recovery flows and deployment operations require review before public production use.

App setup and deployment guide describes native, Docker and GitHub workflows. Provider keys, CVs, profiles, email content and browser state must never enter source commits, build contexts or public artifacts.
